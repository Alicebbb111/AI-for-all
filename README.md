# OmniTransit v5

> คู่มือฉบับเต็ม (ตั้งแต่ clone → รัน → ใส่ API Key → prompt สำหรับโยนให้ AI): **[GUIDE.md](GUIDE.md)**
ระบบสาธิตจำลอง (simulation demo) สำหรับบริหารรถโดยสารนำร่อง 1 สาย — จตุจักร ↔ หัวลำโพง บนแนวถนนจริงในกรุงเทพฯ ตามหลัก "รถมาตามรอบ รู้ข้อมูลจริง ขึ้นรถได้อย่างเป็นธรรม"

## เริ่มใช้งาน (Node.js 18+ — ไม่ต้องติดตั้งอะไรเพิ่ม)

```zsh
cd <โฟลเดอร์โปรเจกต์>     # เช่น ~/work space/antigarvity/ai-forall
./start.sh                # หรือ node server.js
```
เปิด http://localhost:8787/ · เปิดจากมือถือใน Wi-Fi เดียวกัน: ใช้ที่อยู่ (LAN) ที่เซิร์ฟเวอร์พิมพ์ให้ตอนสตาร์ต · เปลี่ยนพอร์ต: `PORT=3000 ./start.sh` · หยุด: Ctrl+C

### เปิดใช้ AI พยากรณ์ความแน่น (OpenAI — ทางเลือก)

คัดลอก `.env.example` เป็น `.env` แล้วใส่ `OPENAI_API_KEY=sk-…` (รองรับ gpt-4o-mini / gpt-4o)
จากนั้นรีสตาร์ตเซิร์ฟเวอร์ หรือวาง Key ชั่วคราวที่ปุ่ม **เครื่องมือ > OpenAI API** มุมขวาบนของหน้าเว็บ
ไฟล์ `.env` ถูก .gitignore ไว้แล้ว — ห้ามใส่ Key ในไฟล์ที่ git ติดตาม เช่น `.env.example`

### เส้นทางบนแนวถนนจริง (OSRM + OpenStreetMap)

เรขาคณิตเส้นทางระดับจุดยอด (ทุกโค้ง/ทุกแยกของถนนจริง) เก็บใน `engine/route_geo.js` ซึ่งเป็นไฟล์
GENERATED จากเครือข่ายถนนจริงของ OpenStreetMap ผ่าน OSRM — **แก้ป้าย/ย้ายป้าย/เพิ่มป้าย** ให้แก้
รายการ `STOPS`/`VIAS` ใน `scripts/build_route.js` แล้วรัน:

```zsh
node scripts/build_route.js   # ต้องต่ออินเทอร์เน็ต · สคริปต์จะจูนตำแหน่งป้ายให้เกาะถนนหลักอัตโนมัติ
```

สคริปต์จะเลือกจุดขึ้น-ลงบนถนนให้เอง (กันป้ายไปเกาะทางคู่ขนานลอย/ทางวิ่งขากลับจนเส้นทางต้องวนย้อน)
และใช้จุดบังคับแนว (via) ที่ถนนหลักตามพิมพ์เขียว: พหลโยธิน – พญาไท – เพชรบุรี/ราชปรารภ –
ราชดำริ/พระราม 1 – พญาไทใต้ – พระราม 4 – แยกมหานคร–สี่พระยา ฝั่งหน้าสถานีกรุงเทพ (หัวลำโพง)

หน้าเว็บโหลดเรขาคณิตครั้งเดียวทาง `GET /api/route.geo.json` (สถิต) ส่วนข้อมูลสดทาง SSE จะส่งเฉพาะ
สภาพจราจรรายโซน (~150 ม./โซน) + ตำแหน่งรถ — ไม่แนบเส้นทางซ้ำทุกวินาที

## หลายเส้นทาง — สลับสายได้ทันที (Multi-Route)

เลือกสายจากเมนูบนหัวแผนที่หน้าผู้โดยสาร — ทุกสายจำลองบน**แนวถนนจริงของกรุงเทพฯ** (พิกัด WGS84 จุดสำคัญ
แยก/สถานี) ระบบจะรีเซ็ตเวิลด์คู่ขนาน ตารางเวลา แผนที่ และป้ายทั้งหมดให้ตรงกับสายที่เลือกโดยอัตโนมัติ:

| สาย | เส้นทาง | แนวถนนหลัก | ป้าย |
|---|---|---|---|
| R1 สายนำร่อง 1 | จตุจักร ↔ หัวลำโพง | พหลโยธิน – พระราม 1 – พญาไท – ราชดำริ – จรัสเมือง | 13 |
| R2 สุขุมวิท | อนุสาวรีย์ชัยสมรภูมิ ↔ บางนา | สุขุมวิทตลอดแนว (ชิดลม – อโศก – ทองหล่อ – เอกมัย – อ่อนนุช) | 11 |
| R3 ลาดพร้าว | จตุจักร ↔ วังหิน | ลาดพร้าว – รัชดาภิเษก (ห้าแยกลาดพร้าว – เวชธานี – สุทธิสาร) | 7 |
| R4 พระราม 4 | อนุสาวรีย์ชัยสมรภูมิ ↔ แยกเจริญกรุง | พญาไท – ปทุมวัน – พระราม 4 – งามวงศ์วัล (สาทร) | 7 |

- API: `GET /api/routes` (ทะเบียนสาย) · `POST /api/control {"action":"route","value":"R2"}`
- สายนำร่อง 1 ยังเป็นสาย "เชิงลึก" เต็มรูปแบบ (โปรไฟล์ความต้องการจูนจริง) ส่วนสายอื่นใช้โปรไฟล์เชิงประจักษ์ตามลักษณะย่าน

## ฟีเจอร์หน้าผู้โดยสาร (Passenger+)

- **ติดตามรถคันนี้** — แถบสถานะบอก "อีกกี่ป้าย · อีกกี่นาที" สดทุกวินาที แผนที่เลื่อนตามรถเมื่อหมุดหลุดกรอบ
  และ**ประกาศเสียงภาษาไทยเมื่อรถเหลือ ≤ 2 ป้ายหรือ ≤ 5 นาที** — ช่วยผู้สูงอายุ/ผู้มองจอไม่ทัน
- **ป้ายโปรด** — เก็บได้ 5 ป้าย (localStorage) สลับป้ายด้วยชิปด้านบนช่องค้นหา
- **ป้ายใกล้ฉัน** — ใช้ GPS หาป้ายใกล้สุดพร้อมระยะทาง (ปฏิเสธสิทธิ์ได้อย่างสุภาพ ระบบไม่พัง)
- **แชร์ป้าย / ลิงก์ตรง** — `?stop=S09&dir=1&bus=B03` เปิดแล้วเจอป้าย/ทิศ/รถที่ติดตามทันที
- **ภาพบรรยากาศจริงรายป้าย** — รูปจาก Wikimedia Commons 13 ป้าย เสิร์ฟจากเซิร์ฟเวอร์นี้ (ใช้งานได้แม้ออฟไลน์)
  เครดิต/ลิขสิทธิ์รายรูปใน `public/img/stops/credits.json` และแสดงซ้อนขอบรูปในหน้าเว็บ
- **แผนที่อ่านง่าย** — ชื่อป้ายแสดงตลอด (หัว-ท้ายสายเน้นพิเศษ) เส้นไหลบอกทิศเดินรถ ป้ายรหัสรถใต้หมุด แผงสรุปมุมแผนที่
- **ผู้ช่วยตัดสินใจ "ขึ้นเลย หรือรอ?"** (ไม่มีใน Google Maps/viaBus/ThaiSmileBus) — เทียบพยากรณ์ไหลสะสม
  ของรถสองคันถัดไป แล้วแนะนำตรงๆ: ถ้าคันแรกเสี่ยงขึ้นไม่ได้ ≥40% และคันถัดไปอีก ≤12 นาที ว่างกว่าชัดเจน
  → "แนะนำให้รอ" พร้อมเหตุผลตัวเลข · ทุกคันในรายการถัดไปมีชิป "% เสี่ยงขึ้นไม่ได้" ให้เทียบเองได้
- **ขนาดตัวอักษร 4 ระดับ (A− ถึง A++)** — ในเมนูเครื่องมือ จำค่าไว้เครื่องละ สำหรับผู้สูงอายุ/สายตาไม่ดี
- **ตารางเวลาตรงทิศ** — สลับขาไป/ขากลับแล้วตารางเปลี่ยนตาม (fwd/rev แยกจริง)
- ความเร็วเวลาจำลองเริ่มต้น **×1 เรียลไทม์** ให้รถเคลื่อนที่สมจริง (19–22 กม./ชม. ตามจราจร) — เร่งได้ที่หน้า จำลองเหตุขัดข้อง

## กลไกสำคัญ (ตรวจสอบย้อนได้ในโค้ด)

### 4 สมการหลักของเอนจินพยากรณ์ (เชื่อมกันเป็นลูกโซ่)

1. **การไหลสะสมรายป้ายล่วงหน้า (Stop-by-Stop Predictive Load Propagation)** — `world.js: propagateLoad()`
   จำลองคนขึ้น-ลงทุกป้ายระหว่างรถ k กับป้ายเป้าหมาย m: คนลง `A_hat[j] = N_hat[j-1] × alightingProb[j]`
   (ตารางสัดส่วนคนลงประจำป้ายใน `data.js` — ป้ายใหญ่อย่างสยาม/ประตูน้ำคนผลัดเปลี่ยนสูง),
   คนรอ `D_hat[j] = λ[j](t_arrival) × rain × H[j] + คิวค้าง` โดย H[j] = ช่องไฟคงเหลือ (H_front − ETA ถึงป้าย j)
   กันการนับคนซ้ำกับรถคันหน้า, คนขึ้นได้จริง `B_hat[j] = min(D_hat, C_max − ที่ว่าง)` และ `N_hat[j] = N_hat[j-1] − A_hat + B_hat`
   ผลลัพธ์ (prop รายคัน) แสดงในหน้าผู้โดยสาร: "คนบนรถขณะนี้ X ± σ คน → คาดเมื่อถึงป้ายคุณ Y ± σ คน (โอกาสขึ้นไม่ได้ Z%)" พร้อมไทม์ไลน์ป้ายระหว่างทาง
2. **ETA คูณขวักไขว่ (Coupled ETA)** — `world.js: runTimeSec() + propagateLoad()`
   `ETA(k→m) = Σ ระยะ/ความเร็ว EWMA รายโซน + Σ DwellTime[j] + Σ เวลารอไฟแดงแยกหลัก`
   โดย `DwellTime[j] = (tau_0=9 วิ + α·B_hat + β·A_hat) × 1.35 เมื่อ N_hat/C_max > 0.75`
   (α = วินาที/คนขึ้น: รถเก็บเงินสด 2.2, EV 1.6 · β = 1.4 วิ/คนลง) — หน้าผู้โดยสารแตกตัวให้เห็น "วิ่ง X นาที + จอดรับ Y ป้าย ≈ Z นาที"
3. **ตรวจข้ามกล้อง AI กับเวลาจอดจริง + ความไม่แน่นอนสะสม (Bayesian Vision-Dwell Cross-Check)** — `world.js: departStop()/arriveStop()`
   `B_implied = (actualDwellSec − tau_0)/α` → `B_corrected = 0.85·B_cam + 0.15·B_implied` เมื่อ B_cam คือยอดจากกล้อง AI มุมสูงเหนือประตู (Overhead Edge-AI Vision — ตรวจจับศีรษะ-ไหล่ข้ามเส้น Virtual Tripwire ประมวลผล On-Device บน Edge NPU ไม่เก็บภาพใบหน้า สอดคล้อง PDPA 100%) ปรับยอดอัตโนมัติ;
   ทุกป้ายที่อ่านจากกล้อง AI `σ = √(σ² + 1.1²)`, ทุกป้ายพยากรณ์ล่วงหน้า `σ = √(σ² + 2.2²)`,
   รีเซ็ต σ = 0 เมื่อถึงอู่ปลายทางหรือผู้สำรวจกดยืนยันยอดจริง — แสดงเป็น "34 ± 3 คน" ตลอดระบบ
   ความแม่นของสมการนี้วัดจริงได้ที่หน้า KPI (MAE พยากรณ์คนบนรถ + สัดส่วนอยู่ในกรอบ ± sigma)
4. **การหน่วงปล่อยรถสองทิศของนายท่า (Daganzo's Two-Sided Headway Holding)** — `world.js: holdRecommendation()/checkTerminalGaps()`
   `rawHold = 0.5·(H_target − H_front) + 0.25·(H_back − H_front)` → ปัดเป็นนาทีในกรอบ 0–5 นาที;
   คุมเงื่อนไขบังคับ: เวลาพักขั้นต่ำ 6 นาทีไม่ถูกตัด และไม่ลดเที่ยววิ่งขั้นต่ำ —
   หน้านายท่าแสดงเหตุผลบรรทัดเดียว เช่น "คันหน้าห่างเพียง 6.9 นาที (คันหลัง 16 นาที · รอบเป้า 8 นาที) แนะนำชะลอปล่อย 3 นาที"

ทั้ง 4 สมการถูกส่งเป็นฐานคณิตศาสตร์ให้ OpenAI ในฟิลด์ `deterministic_model` ของ `/api/ai/predict-crowd`
(currentOnboard, propagatedEstimateAtTargetStop, uncertaintySigma, expectedIntermediateBoardings/Alightings, headwayMin, coupledEtaMin)

- **สมการสมดุลผู้โดยสาร** — นับขึ้น/ลงรายป้าย (กล้อง AI เหนือประตู Edge Vision จำลอง + ผู้สำรวจ) clamp ไม่ติดลบไม่เกินความจุรุ่นนั้น รีเซ็ต 0 ที่อู่พร้อมตรวจยอด
- **ระดับความแน่น 4 ระดับ** — คิดจากสัดส่วนเบาะ/พื้นที่ยืนของรถแต่ละรุ่นจริง (34/28/31 ที่นั่ง + จุดวีลแชร์) ไม่ใช้เปอร์เซ็นต์ตายตัว
- **กฎ GPS 90 วินาที** — พิกัดเก่าเกินเกณฑ์ = ปลดสถานะสดทันที สลับตารางเดินรถมาตรฐาน ไม่แสดงเวลาปลอม
- **Bus Bunching** — เสนอหน่วงเวลาปล่อยคันถัดไปจากต้นสายภายในกรอบ ±5 นาที นายท่ากดปุ่มเดียวตัดสินใจ บันทึก Audit Log ทุกครั้ง (ห้ามเร่งกลางทาง ห้ามข้ามป้าย ห้ามตัดเที่ยว ห้ามตัดพัก)
- **KPI คู่ขนาน** — เวลารอเฉลี่ย/P90/Pass-up/CV เทียบก่อน-หลังจากสองเวิลด์ที่ได้ demand ชุดเดียวกัน
- **โมเดล AI** — Shadow → อนุมัติ (เกณฑ์ MAE ดีขึ้น ≥10% บนเฟสทดสอบ) → Rollback ได้ตลอด
